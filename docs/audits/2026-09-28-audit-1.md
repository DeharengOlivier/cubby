# Audit 1: cubby (level L2) at ba9d072 (2026-08-28)

Standards: `CODING-RULES.md` and `SECURITY-CHECKLIST.md`, version 2026-09-25.1.
Method: `/audit-code` procedure, scorecard sub-criteria, evidence from a fresh clone of
`main` (the maintainer's working folder was byte-identical except an untracked `uv.lock`).

Cubby is a local CLI and background agent (launchd/systemd) that moves files out of a
Downloads folder into category folders, with a filename, content and type cascade and an undo
journal. The code is small (1 143 statements), carefully commented and well tested at unit
level (210 tests, 92 % branch coverage, strict mypy, ruff, bandit, pip-audit in CI). But the
mode the product exists for, the unattended agent, is the least safe one: **files sorted by
`cubby watch` (the agent) are never journaled, so `cubby undo` cannot put them back**, one
failing file aborts a run and loses the journal of the files already moved, and the service
commands report success when the service manager refused them. The most important thing to
fix is that safety net.

Level: **L2 PRODUCT**. It acts on the user's real files, unattended, with bounded and
recoverable impact (moves inside one folder, never deletes except opt-in duplicates).

## Release blockers (applicable P0 failed or not verified)

FAIL:

1. **SEC-GOV-01**: no readiness register. No release gate can be evaluated.
2. **SEC-19-004** (no partially valid state): a failure on the Nth file aborts the run after
   N-1 moves and the journal is never written (measured: 2 files moved, `last_run() is None`,
   `sorter.py:83-116`). Those files cannot be undone.
3. **SEC-08-003** (no command line built from user data): the systemd unit joins the program
   arguments with spaces (`systemd.py:42`). Measured with `--source "/home/x/My Downloads"`:
   `ExecStart=/usr/bin/cubby watch --source /home/x/My Downloads`, which systemd splits into two
   arguments; `%` and `$` in a path are also expanded by systemd.
4. **SEC-13-001**: no lockfile committed; CI runs `pip install -e ".[dev]"` unpinned.
5. **SEC-13-009**: CI actions pinned to mutable tags (`actions/checkout@v4`).
6. **SEC-14-001**: `enforce_admins: false`, no pull request required: 125 commits, 0 PRs,
   and commit 75c905c reached `main` with a failing CI run (run 33173924911).
7. **SEC-14-007**: the workflow declares no `permissions:`; the token gets the repository
   default.

NOT_VERIFIED:

8. **SEC-01-001..007**: no threat model; `SECURITY.md` covers scope and trust but not the
   entry points and high-impact operations as a list.
9. **SEC-07-005**: the parsers at entry points (config TOML, journal lines, document dates)
   are not fuzzed; only the engine is exercised by a seeded random loop (`test_fuzz.py`).
10. **SEC-13-002**: the security job installs `.[dev]` only, so the optional extractors
    (`pypdf`, `python-docx`, `openpyxl`), which parse untrusted downloads, are never scanned.
11. **SEC-18 application DoS**: `pypdf` parses untrusted PDFs in process with no timeout
    (`extraction.py:97-104`); a crafted file can stall the agent. External tools have a 15 s
    timeout, the in-process parser does not.
12. **SEC-14-003** (MFA): not observable from here.

## Remediation plan (impact / effort)

Delivered as separate pull requests, each with CI and a recorded independent review.

1. [3h, high] **Make every move undoable and every run whole.** Journal the agent; record a
   run even when it fails part way; isolate per-file failures (the run continues, reports them,
   exits non-zero); undo of a deduplicated file restores a copy instead of moving the kept one;
   versioned journal schema that still reads v1 lines; no-clobber move. -> COR-02 4->9,
   REL-05 3->9, REL-04 4->8, SEC-19-004 PASS.
2. [2h, high] **Loud failures at the service boundary.** Quote the systemd command line
   (escape `%`, `$`, spaces); check return codes and add timeouts on `launchctl`/`systemctl`;
   refuse to watch or install a missing folder; a run lock so two cubby processes never touch
   the same folder. -> REL-07 4->9, SEC-08-003 PASS.
3. [2h, high] **Supply chain and CI.** Commit `uv.lock`, CI installs with `uv sync --locked`,
   actions pinned by SHA, `permissions: contents: read`, format check, scan the extras,
   gitleaks over full history, Dependabot for pip and actions, import-linter contract for the
   layering, changed-code coverage threshold. -> MNT-01, MNT-04, MNT-07, RCV-05, SEC-13, SEC-14.
4. [2h, med] **Observability for a desktop agent.** JSON-lines log with a run id at a
   platform-correct path, size-rotated; a run ledger (status, counts, failures) that `status`
   reads; `status` queries the real service state. -> OBS-01, OBS-04, OBS-07.
5. [1h, med] **In-process parsing bounded.** Run `pypdf` in a child process with a timeout.
   -> SEC-18 DoS, REL-01.
6. [4h, high value] **Features.** `cubby explain FILE` (which stage and which rule decided),
   `cubby init` (starter config), `cubby history` (recent runs from the ledger), `undo --run`,
   `ignore` glob patterns, per-category age rules not needed yet. -> USE-03, product value.
7. [2h, med] **Tests that attack.** Hypothesis properties on dates, durations, naming, the
   journal round trip and config parsing; targeted mutation on containment and the journal;
   end-to-end agent journey in a subprocess; network guard. -> TST-02, TST-03, TST-08, SEC-07-005.
8. [1h, med] **Governance.** Readiness register, threat model, runbook, branch protection
   with PR required and no admin bypass, release 0.2.0 with built artifacts attached and a
   rehearsed rollback to 0.1.0. -> PRC-01, PRC-02, PRC-04, PRC-06, RCV-03, RCV-06, SEC-GOV-01.
