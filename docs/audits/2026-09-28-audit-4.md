Cubby is a local CLI and per-user agent (launchd or systemd `--user`) that moves the files of
one folder into category subfolders, reversibly, with no network, no accounts and no data of
its own beyond an undo journal, a run ledger and a log. Since v0.3.0, nine pull requests
(#20 to #28) worked through audit 3's plan, and I confirmed most of it by measurement: hostile
file names are now escaped in every human and `--json` output I exercised (SEC-08-004, fixed),
converter failures are logged and counted, the agent's pass memory is bounded (121 bytes per
file measured here), a flaky-rate script exists and reports 0.9% against a 2% budget, and a
required `review record` status holds review evidence on every PR. The code is in very good
shape. The gate is still blocked by the unconfirmed 2FA. I also found one new P0 problem, in
the verification process rather than the product: during the PR #27 work, the test suite wrote
into the maintainer's real `~/.local/state/cubby/cubby.log`, because test isolation relies on
the code under test honoring `CUBBY_STATE_DIR` and a mutant broke that. The most important
thing to fix is small: redirect `HOME` for the whole test session and confirm 2FA.

## Release blockers (applicable P0 failed or not verified; distinguish the two)

FAIL:
1. **SEC-GOV-02** (safe verification: isolated data for active tests), low severity, process
   only. Measured on this host: `~/.local/state/cubby/cubby.log` (the real state folder, not
   touched by this audit, which ran every command with `HOME` set to a temporary folder) holds
   two lines, `{"ts": "2026-09-28T18:05:21", "level": "INFO", "msg": "a line from the test
   suite", "version": "0.3.0"}` and the same at 18:13:21. That message exists only in
   `tests/test_state_isolation.py:48`. Version 0.3.0 and the times (16:05Z and 16:13Z) fall in
   the PR #27 window (commits 16:02Z to 16:14Z, before the 0.4.0 bump in #28). The PR #27 review
   record reports running mutants of `state.py:71`, including "M7: fallback
   `_default_state_dir()/cubby.log`", which sends that test's log line exactly there when
   `HOME` is real, and it states "the real HOME, `~/.local/state/cubby` and service managers
   were not touched". The evidence contradicts that sentence. Attribution to that exact mutant
   is inferred, not proven; that a run of this project's suite wrote to the real state folder
   is proven by the file.
   Root cause: `tests/conftest.py:31-41` isolates state by setting `CUBBY_STATE_DIR`, which
   only works while the code under test reads it correctly; `HOME` is not redirected for
   in-process tests. The guard `test_this_session_wrote_nothing_to_the_real_state_files`
   (`tests/test_state_isolation.py:52-62`) only looks for the session's temp path in those
   files, so a line without a path passes it. The register marks SEC-GOV-02 PASS.
   -> consequence here: two stray log lines. The same mechanism corrupted the real undo journal
   once before (docstring of `tests/test_state_isolation.py:3-7`). The shipped artifact is not
   affected.
