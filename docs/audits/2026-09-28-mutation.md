## What round 1 showed

Surviving mutants that pointed at real gaps in the tests (the code was right, nothing
checked it):

- **Dedupe could delete a different file without a test failing.** Replacing the content
  digest by a constant, or answering "identical" when a file cannot be examined, survived:
  no test compared two same-sized files with different bytes. A bug there deletes a file that
  is not a duplicate. Now pinned by `test_files_of_the_same_size_but_different_bytes_are_not_identical`,
  `test_dedupe_keeps_a_same_named_file_with_other_bytes`, `test_a_file_that_cannot_be_examined_is_not_identical`.
- **A symlink could be turned into a hard link to its target** (`is_file() and not is_symlink()`
  weakened to `or`): `test_a_symlink_is_moved_as_a_symlink`.
- **Undo**: stopping at the first failed entry instead of continuing, not counting or not
  settling vanished files, not recreating a removed source folder, not reporting the run id.
- **Journal**: settlement verdicts, version 1 sequence numbers and ops, a versioned line that
  carries `moves` being read as version 1, the compaction boundary.
- Skip reasons were only checked as substrings, so a mangled reason passed.

The property tests written in the same change also found a real defect in the code: a file
name containing U+2028, U+2029 or U+0085 lost its journal entry (see `CHANGELOG.md`).

## A survivor that was not equivalent

Round 3 listed `Journal._append` 6, 8 and 11 (`ensure_ascii=False` changed to `True`) as
equivalent. The independent review of PR 4 showed otherwise: on Linux a file name that is not
valid UTF-8 is held as surrogate characters, which `ensure_ascii=False` cannot encode, so the
journal refused the name after the file had moved and the move could not be undone. The
mutant was the correct code. Cubby now writes every state file as ASCII JSON, with the
reproducer `test_a_name_that_is_not_utf8_can_be_sorted_and_undone`, and the journal property
test now draws surrogate characters too. Lesson recorded: an "equivalent" verdict on an
encoding mutant needs a test over the full input alphabet, not an argument.

## Round 5: two survivors that were real gaps

- `move_no_clobber` 8 (`add_note(None)`): nothing tested a move whose clean-up fails too. The
  mutant raises a `TypeError` in place of the permission error that explains the failure.
  Now `test_a_move_whose_cleanup_also_fails_raises_the_first_error_and_names_the_link`.
- `Journal.compact` 18 (`<` to `<=`, always rewrite): nothing checked that a compaction which
  drops nothing leaves the file alone; rewriting 24 MB every time would bring back the cost
  the change removed. Now `test_compaction_that_drops_nothing_does_not_rewrite_the_file`.

Round 6 reran every mutant after those tests (`rm -rf mutants`, `make mutation`).
