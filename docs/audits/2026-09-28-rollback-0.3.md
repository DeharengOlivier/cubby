# Rollback rehearsal: 0.3.0 to 0.2.0 and back

Date: 2026-09-28. Operator: the maintainer's release session, in a throwaway `HOME` with
`XDG_CONFIG_HOME`, `XDG_STATE_HOME` and `CUBBY_STATE_DIR` unset. No service manager was
involved: the agent's unit is removed before a rollback (`docs/RUNBOOK.md` section 4), and
`cubby install --help` and `cubby watch --help` print the same flags in both versions.

Builds: 0.2.0 from tag `v0.2.0` (db85fec), 0.3.0 from `release/0.3.0`, each in its own venv.

| Step | Command | Result |
|---|---|---|
| 1 | 0.3 `cubby init`, then `cubby run` on a PNG and a text invoice | rc 0, `Images/photo.png`, `Invoices/2026-08/a.txt` (by content) |
| 2 | 0.2 `cubby run` with the config 0.3 wrote | rc 2: `config error: unknown key 'late_content_patterns' in category 'Invoices'` |
| 3 | 0.2 `cubby history` | rc 0, lists the 0.3 run |
| 4 | 0.2 `cubby undo` (last run made by 0.3) | rc 0, both files restored |
| 5 | delete the `late_content_patterns` list, 0.2 `cubby run` | rc 0, the invoice goes to `Documents` (by type) |
| 6 | 0.2 `cubby undo` | rc 0, three files restored |
| 7 | restore the 0.3 config, 0.3 `cubby history`, `cubby undo`, `cubby doctor` | rc 0, both runs shown as undone, nothing left to undo, doctor rc 0 |
| 8 | fresh home: 0.2 `cubby run`, then 0.3 `cubby undo` | rc 0, both files restored |

Finding: the only incompatibility is the new config key (step 2). `docs/RUNBOOK.md` section 4
now says to keep a copy of the config and delete that list before running 0.2. The journal and
the ledger are read by both versions in both directions.
